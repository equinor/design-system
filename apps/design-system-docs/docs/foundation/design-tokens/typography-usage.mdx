[Overview](./typography.mdx) gives you the question to pick a role with, and the groups that each
role's steps fall into. This page turns both into specific answers, with a role and a step for each
case. It also gives the header step for each heading level, shows the tokens on a worked example,
and lists what tends to go wrong.

## Decision table

The rows are sorted by role, and within a role by the groups in [choosing a step](#choosing-a-step).
If your case is not here, ask whether the text wraps to find the role, and the nearest row in that
role is usually right. Headers are always `medium`, and a `label` or `body` row without a weight
uses `normal`.

## Choosing a step

Within a role, the steps fall into groups by where the text sits. Components use the smaller
steps: `label.xs` to `label.lg`, and `body.sm` and `body.md`. The page around the components uses
the rest. Its headings use `header`, and its running text uses `body.lg` and `body.xl`. The
page-layout steps, which are `label.xl` to `label.5xl`, `body.2xl` and `body.3xl`, and `header.sm`
and `header.xs`, set the navigation, key figures, the intro text of front pages and the headings
in the page chrome. They are normal steps for page layouts, such as dashboards, overview pages and
front pages.

The tables name the steps without their role. For the sizes, see
[the steps on the overview](./typography.mdx#the-steps), or [the type scale](./typography-scale.mdx)
for all three densities.

### Header

Headers are set in Equinor, always in `medium`. The first three groups follow the heading levels,
and [heading levels](#heading-levels) explains how to use them when a heading needs to look larger
or smaller than its level.

| Group                            | Steps            | Use                                                                                                                                                         |
| -------------------------------- | ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Page title                       | `4xl`            | the `h1`                                                                                                                                                    |
| Sections                         | `3xl`, `2xl`     | `h2` and `h3`                                                                                                                                               |
| Subsections                      | `xl`, `lg`, `md` | `h4`, `h5` and `h6`                                                                                                                                         |
| Headings with no default element | `sm`, `xs`       | page-chrome headings that must look smaller than an `h6`: footer column headings, an "On this page" heading, and section headings in a filter or side panel |

The last group has no heading element of its own. Use the element that fits the structure of the
page, and set it to `header.sm` or `header.xs` in CSS, in the same way as the example under
[heading levels](#heading-levels).

- **These steps are headings, so they name what follows them.** They are not an eyebrow or an
  overline, the small text above a title that says what category it belongs to. EDS 2.0 has no
  overline style.
- **Mind legibility with `header.xs` in Compact.** Compact sets it one step smaller on the type
  scale, which is small for a heading, so check that it is still easy to read where you use it.

### Label

Labels are set in Inter, on one line. `normal` is the default weight, and `medium` sets buttons,
badges and titles apart.

| Group             | Steps        | Use                                                                                                                                                                                                          |
| ----------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Inside components | `xs`         | indicators such as Optional and Required, adornments such as a prefix, suffix or unit, menu group titles, and avatar metadata                                                                                |
|                   | `sm`         | card content and metadata, badges in `medium`, small buttons in `medium`, and the name beside an avatar                                                                                                      |
|                   | `md`         | the default: a field's label, placeholder and value, buttons in `medium`, checkbox, radio and switch labels, chips, tabs, menu items, links, breadcrumbs and tooltips. Card and accordion titles in `medium` |
|                   | `lg`         | dialog titles, in `medium`                                                                                                                                                                                   |
| Page layout       | `xl`         | top-level navigation, the app or product name in the page header, and a prominent call to action on an overview page                                                                                         |
|                   | `2xl`, `3xl` | key figures in a row of stat tiles: `3xl` for the main value, and `2xl` for the values beside it                                                                                                             |
|                   | `4xl`, `5xl` | the one figure a page is about: a large readout, a timer, or a value on a control-room or wall display that is read from a distance                                                                          |

Key figures are `label` because each one is a value on one line, and Inter has tabular figures for
values that update. The figure's own label, such as "Production rate", is `label.sm` or `label.md`.
A key figure may look larger than the page's `h1`, and that is intended: the `h1` names the page,
and the figure is the value the page is there to show.

### Body

Body text is set in Inter and wraps, with a line height set for reading. `normal` is the default
weight, and `bold` is for emphasis.

| Group             | Steps        | Use                                                                                                                                                            |
| ----------------- | ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Inside components | `sm`         | helper and error text under a field, footnotes, source notes under charts and tables, and disclaimers                                                          |
|                   | `md`         | dialog content, banners, accordion content, snackbars, and descriptions in side panels                                                                         |
| Page              | `lg`         | running text on a page                                                                                                                                         |
|                   | `xl`         | the ingress, the introductory paragraph under a page title                                                                                                     |
| Page layout       | `2xl`, `3xl` | intro text on front pages and overview pages, pull quotes, a short statement on an onboarding or empty page, and running text on displays read from a distance |

Text inside a component that can wrap is `body`, even when it is one line today. A banner message
or a snackbar is `body.md`, so a longer message wraps with the line height it needs.

## Always set the pair

A step is two tokens, and they go together. Take the font size and the line height from the same
role and the same step:

```css
.caption {
  font-size: var(--eds-typography-label-sm-font-size);
  line-height: var(--eds-typography-label-sm-line-height);
}
```

Leave out the line height and the text inherits one from its parent. Inside a paragraph, that is
the paragraph's line height, so a caption ends up with the leading of running text. Mixing steps,
such as a `label.sm` size with a `label.md` line height, breaks the rhythm in the same way, just less
visibly.

## Building hierarchy

Reach for size first, then weight, then colour, and change as little as you need to:

1. **Size**, one step at a time. Neighbouring steps are close on purpose.
2. **Weight**, with `medium` in a label. `bold` is for strong emphasis, so keep it rare.
3. **Colour**, with `text.secondary` for text that matters less.

## Heading levels

Each heading level has a header step that goes with it:

| Element | Step         |
| ------- | ------------ |
| `h1`    | `header.4xl` |
| `h2`    | `header.3xl` |
| `h3`    | `header.2xl` |
| `h4`    | `header.xl`  |
| `h5`    | `header.lg`  |
| `h6`    | `header.md`  |

Use this mapping as guidance, and depart from it when a layout needs to. Treated as a strict rule,
it leads to a disagreement between design and code that comes back every time.

Designers pick a text style by its size. When a layout needs large text, the style for an `h1` is
the one that looks right, so a second `h1` appears in the design. Developers read `h1` as
structure: it is the top-level heading, and a document has one. To the developer, the design looks
wrong. To the designer, the objection is about something they were not modelling.

The answer is to choose the element and the step separately. Keep the element that is correct for
the structure of the page, and give it the header step it needs to look right. Here a section
heading on an overview page is set at the size of a page title, and it stays an `h2`:

```css
.overview-page h2 {
  font-family: var(--eds-font-family-header);
  font-size: var(--eds-typography-header-4xl-font-size);
  line-height: var(--eds-typography-header-4xl-line-height);
  font-weight: var(--eds-font-weight-medium);
}
```

So a design can set any heading at any header step, and the page still has one `h1`, with the
levels below it in order.

## Running text

Anything that wraps is `body`, and its line height is set for reading. Keep each line between 55
and 80 characters, including spaces. Shorter lines make the eye jump back too often, and longer
lines make it hard to find the start of the next one.

## What our components use

In the Figma component library, single-line text uses `label.xs` to `label.lg`, and most of it is
`label.md`. Text that wraps inside a component, such as dialog content or a banner message, is
`body.md`, and the helper text under a field is `body.sm`. No component uses `header`. Headers
belong to the page around the components, together with running text and the page-layout steps.

In code, no EDS 2.0 component reads these tokens yet. The `/next` components still use the
2.0.0-beta typography names, and they will move to these tokens.

## Mistakes that survive review

These look right on screen, which is why they get through.

- **Binding the family one layer too low.** In Figma, bind `font-family.ui` or
  `font-family.header`, not `family/ui` from the hidden font collection. The value is the same
  today, but the hidden layer is internal and can change without notice.
- **Binding line height to a spacing token.** Line heights resolve to the same values as spacing, so
  a spacing token in the line-height field looks correct. It stops being correct the day either
  scale changes. Use the line height of the step you set the size from.
- **Skipping a library update after a rename.** When a style or variable is renamed, Figma brings
  in the new one and keeps the old one bound where it was used. Text on an old name still renders,
  but it no longer follows the system. Accept the update and rebind.
- **Setting a font size alone in code.** The text inherits a line height from its parent and looks
  close enough until it wraps, or sits next to something that set the pair.

## Accessibility

- **The smallest step supports a larger label.** `label.xs` is the smallest step, and Compact makes
  it smaller still. Use it for short text that sits beside a larger label and adds to it, such as
  an Optional indicator or the unit after a value, and never for primary content or for text that
  has to be read on its own.
- **Keep heading levels in order.** Screen reader users move through a page by its headings, so the
  heading elements must follow the structure of the page, whatever header step each one is set at.
- **Text must survive the user's own spacing.** WCAG 2.1 success criterion 1.4.12 asks that content
  still works when someone increases line height and the spacing between letters, words and
  paragraphs. Components
  must not clip or overlap text when that happens, whichever role the text uses.
- **Offer a way back from Compact.** If you use Compact for a whole product, give users a way to
  switch to Comfortable. Smaller default text should not be a one-way door.
- **Do not rely on weight alone.** Pair a change of weight with size, position or colour, so the
  hierarchy is clear to someone who cannot see the difference in weight.

## Do's and Don'ts

:::info **Do**

- Ask whether the text wraps, and pick `label` or `body` from the answer
- Pick the heading element by the structure of the page, and its header step by how it should look
- Take the font size and line height from the same step
- Use sentence case for headers and labels, capitalising only the first word
- Let density resize text, with one attribute on a wrapper
- Use `text.secondary` to make text matter less, before making it smaller

:::

:::danger **Don't**

- Wrap the text of a button or a chip over several lines. Shorten it instead
- Use `header` for a label that happens to be large, such as a key figure. A header names what
  follows it
- Pick a smaller step to fit a dense view. That reimplements Compact and drifts from every other
  dense view in the product
- Mix typefaces within one piece of UI. Equinor is for headers, Inter for everything else
- Set font weights by number. Use the three weight tokens

:::

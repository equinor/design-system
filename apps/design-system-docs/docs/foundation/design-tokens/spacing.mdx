Spacing in EDS is eleven named steps and nothing else. You apply them directly to `padding`, `gap`
and `margin`, and the value you get depends on the density the element sits in.

These pages document the **3.0.0-beta** spacing tokens. The names are new and so are the values, so
if you are on EDS 1.x or on 2.0.0-beta, see [coming from an earlier version](#coming-from-an-earlier-version).

## The eleven steps

{/* GEN:spacing-steps BEGIN - regenerate with pnpm generate:spacing-reference. Do not edit by hand. */}

| Step | Comfortable | Reach for it when |
| --- | --- | --- |
| `spacing.none` | 0px | removing space on purpose. Better than `0`, because it survives a density change |
| `spacing.4xs` | 2px | hairline separation, and nudging an icon off its text |
| `spacing.3xs` | 4px | padding inside dense controls: chips, badges, tags |
| `spacing.2xs` | 6px | tight control padding |
| `spacing.xs` | 8px | the default gap between a control's own parts, such as an icon and its label |
| `spacing.sm` | 12px | the default gap between related items in a group |
| `spacing.md` | 16px | **the default container padding. Start here** |
| `spacing.lg` | 20px | separating groups inside a container |
| `spacing.xl` | 24px | separating sections |
| `spacing.2xl` | 28px | page-level rhythm, in layouts rather than components |
| `spacing.3xl` | 32px | page-level rhythm, the widest step there is |

{/* GEN:spacing-steps END */}

Values shown are Comfortable, which is the default. All eleven move together when the density
changes, and the names stay put. [The scale](./spacing-scale.mdx) has every value.

:::info Why the numbers are published
2.x hid the values behind abstract names, and the most common complaint was not knowing what
`Medium` meant. You should be able to read `spacing.md` = 16px off this page and off the Figma
variable without opening a generator or a browser inspector.
:::

## Choosing a step

Two questions, in order. They are worth answering in this order because the second one is the one
that keeps a layout consistent across pages.

### 1. Is this inside a component, or between components?

- **Inside** a component: `4xs` through `xs`. A control's own interior, such as the gap between an
  icon and its label, a chip's padding, or a checkbox's offset from its text.
- **Between** components: `sm` and up. Layout space, such as gaps in a list, padding on a card, or
  the separation between two sections.

### 2. How closely related are the two things?

Space is the main signal of grouping, so distance should track relatedness:

| Relationship | Step |
| --- | --- |
| two parts of one control, such as an icon and its label | `xs` |
| two labels in the same field | `xs` |
| two fields in the same fieldset | `sm` |
| two fieldsets in the same form | `lg` |
| two sections on a page | `xl` |

The failure this avoids is picking by how it looks on the screen in front of you, which is how you
end up with `sm` between two sections on one page and `xl` between the same two on another. Pick by
relationship and consistency comes for free.

[Using spacing](./spacing-usage.mdx) has worked examples, a per-case decision table, and the
mistakes that tend to survive review.

## Corner radius travels with spacing

Corner radius is in the same density collection, so a compact component gets tighter corners
without you asking for it.

{/* GEN:radius-steps BEGIN - regenerate with pnpm generate:spacing-reference. Do not edit by hand. */}

| Token | Comfortable | Use for |
| --- | --- | --- |
| `corner-radius.none` | 0px | full-bleed edges and table cells |
| `corner-radius.rounded` | 4px | the default: buttons, inputs, chips |
| `corner-radius.rounded-outer` | 5px | a container wrapping rounded children, so the curves nest instead of pinching |
| `corner-radius.pill` | 9999px | fully round ends: pills, avatars, toggles |

{/* GEN:radius-steps END */}

`pill` is a sentinel rather than a measurement. It is large enough that the browser clamps it to
half the element's height, which is what "fully round" means at any size.

## Density

One attribute resizes the interface. It moves spacing, corner radius and type size together, by one
position each, so proportions hold:

```html
<div data-density="compact">…</div>
```

| Density | Attribute | Use it for |
| --- | --- | --- |
| **Compact** | `data-density="compact"` | dense data: tables, monitoring, dashboards, anything where more rows on screen beats more air |
| **Comfortable** | *(none, this is the default)* | ordinary application UI. If you are not sure, this is the answer |
| **Relaxed** | `data-density="relaxed"` | touch and mobile, and reading-heavy pages where targets need to be larger |

Comfortable is emitted at `:root` rather than behind a selector, so setting nothing gives you
Comfortable. `data-density="comfortable"` is allowed and does no harm.

:::warning `spacious` no longer exists
2.x had a `spacious` density. Its replacement is **Relaxed**. `data-density="spacious"` fails
silently: no error, and you get Comfortable. Search your codebase for it.
:::

Density is not a multiplier and not a `transform: scale()`. [How density works](./spacing-scale.mdx#how-density-works)
covers what it does instead, and why `Compact` is not `Comfortable` × 0.75.

## Coming from an earlier version

Both earlier generations used a different set of names, and neither maps cleanly onto the eleven
steps:

- **EDS 1.x** had eight t-shirt spacers on an 8px grid, with `XX Small` and `X Small` reserved for
  component interiors.
- **2.0.0-beta** split spacing by direction and by component role, with families such as
  `generic-space-*`, `generic-gap-*` and `selectable-space-*`.

Direction is a CSS property now, not part of the token name, so `Space vertical` and
`Space horizontal` both become one step applied to the property you mean. Component-specific
spacing is gone for the same reason colour lost its component tokens: a card and a table row that
happen to share a value should not share a name.

:::note The mapping table is not written yet
The old-name to new-name mapping needs the 2.x families resolved against the eleven steps first,
which is tracked in [equinor/design-system#5121](https://github.com/equinor/design-system/issues/5121).
Until then, re-pick by the two questions above rather than by matching the old value.
:::

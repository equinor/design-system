# Migrating a /next component to the beta tokens

This is the canonical recipe for moving a `/next` component from the legacy 2.x tokens to the redefined tokens from Tokens Studio (the `eds-tokens` beta). The harness entry points (`/token-migration` in Claude Code, the `token-migration` prompt in Copilot and the `token-migration` agent in OpenCode) all defer to this file.

Each component migrates on **colour, spacing and typography in one pass**, with one sub-issue and one PR per component (#5119). Button and Chip are the worked examples:

- [`Button/button.css`](../../packages/eds-core-react/src/components/next/Button/button.css) (#5222)
- [`Chip/chip.css`](../../packages/eds-core-react/src/components/next/Chip/chip.css) (#5225)

Read them before starting. When this doc and those files disagree, the files on `main` are the reference, and this doc should be corrected.

This is a token migration, not a redesign. Leave the component's structure and props alone, apart from the data attributes in step 7.

## 1. Before you start

1. Find the component's sub-issue under #5119 and check for an existing branch or draft PR (`gh pr list --search "<Component>"`). Continue it rather than starting over.
2. Read the decisions the migration depends on:
   - ADR-0027: token structure, the `header`, `label` and `body` roles, the spacing scale.
   - ADR-0028: output, the `@layer eds-tokens` wrap and the publish boundary (point 7).
   - ADR-0029: web typography, one weight per role, no text-box trim.
   - #5692: borders and focus rings are a plain `1px`.
   - #5711: tones are mapped in each component's own CSS.

   ADR-0018 is superseded by ADR-0029. ADR-0017 describes the 2.x spacing tokens (`--eds-selectable-space-*` and friends); the beta names come from ADR-0027.

3. Know where the names live. Always check against `origin/main`, not a stale branch:
   - **Beta bundle to grep:** `packages/eds-tokens/src/tokens/css/variables.css`. Storybook loads it in `packages/eds-core-react/.storybook/preview.css`. It is generated by the Tokens Studio release workflow; never edit it by hand.
   - **Legacy bundle:** `components/next/index.css` imports `@equinor/eds-tokens/css/variables` into `@layer eds-tokens-legacy`, so the beta bundle wins on names both declare. The import can only go when no `/next` component reads a legacy name.
4. Check the open token issues linked from the sub-issue, so you know which gaps are already reported.

## 2. Inventory

List every `--eds-*` reference in the component's CSS with the element and state it styles (`grep -n "eds-" <component>.css`). Split the list into colour, spacing (including corner radius and sizes) and typography. Every line must end up mapped or explicitly reported as a gap.

Also list what has to disappear:

- `text-box` and the `@supports (text-box: …)` blocks
- `--eds-padding-top-baseline`, `--eds-padding-bottom-baseline` and similar cap-height compensation
- per-size font weights such as `--_font-weight-bolder`
- the local data attributes in step 7
- `data-density='spacious'`

## 3. Read the values per state from Figma

Read the variable bindings for every state the component has: default, hover, pressed, focus, disabled, selected, error, and every tone and size. One read of the default state misses the state-specific tokens. Take spacing and typography bindings in the same pass as colour.

Figma and code are one-to-one. If a binding does not match a token that exists, ask design rather than picking the nearest name. If Figma returns raw values with no bindings, look the value up in the beta bundle (follow the `var()` chains, keep only semantic names, and check light, dark and all three densities).

Known and deliberate, so not findings:

- `--eds-background-interactive-{tone}-muted-default` is the same shade as the canvas. Resting muted fills sit quietly on `--eds-background-surface` and gain fill on hover and pressed. Judge fills against the surface, not the canvas.
- Header line heights sit a step above their font size step (ADR-0027).

## 4. Colour

Tones: `accent`, `neutral`, `danger`, `warning`, `success`, `info`.

| Role                                         | Token                                                                                                         |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Emphasis fill, default / hover / pressed     | `--eds-background-interactive-{tone}-emphasis-{default,hover,pressed}`                                        |
| Text and icon on the emphasis fill           | `--eds-text-on-emphasis-{tone}`, `--eds-icon-on-emphasis-{tone}`                                              |
| Muted fill, default / hover / pressed        | `--eds-background-interactive-{tone}-muted-{default,hover,pressed}`                                           |
| Text and icon on the surface or a muted fill | `--eds-text-on-default-{tone}`, `--eds-icon-on-default-{tone}` (also `-on-muted-{tone}` where Figma binds it) |
| Border, emphasis / muted                     | `--eds-border-interactive-{tone}-{emphasis,muted}-{default,hover,pressed}`                                    |
| Link text                                    | `--eds-text-interactive-link-{default,hover,pressed}`                                                         |
| Disabled fill, text, border, icon            | `--eds-{background,text,border,icon}-interactive-disabled`                                                    |
| Focus ring                                   | `--eds-border-interactive-focus`                                                                              |
| Neutral, non-interactive text and icons      | `--eds-text-{primary,secondary,tertiary}`, `--eds-icon-{primary,secondary,tertiary}`                          |
| Surfaces                                     | `--eds-background-{canvas,surface,input,floating,dialog,backdrop,inverted}`                                   |

Follow Figma where it departs from the pattern. For example, Chip's neutral label binds to `--eds-text-primary`, not `--eds-text-on-default-neutral`.

**Tones are mapped per component (#5711).** The bundle has no rule that switches tone from an attribute, so each component maps its tones in its own CSS. Define the default tone's tokens as `--_` slots at the root, and override only the slots under `&[data-tone='…']`. Use the slot names Button and Chip use, so a shared layer can be extracted later:

```css
.eds-button {
  --_bg-emphasis: var(--eds-background-interactive-accent-emphasis-default);
  --_bg-emphasis-hover: var(--eds-background-interactive-accent-emphasis-hover);
  --_bg-muted-hover: var(--eds-background-interactive-accent-muted-hover);
  --_text-emphasis: var(--eds-text-on-emphasis-accent);
  --_text-interactive: var(--eds-text-on-default-accent);
  --_border-interactive: var(--eds-border-interactive-accent-emphasis-default);

  &[data-tone='danger'] {
    --_bg-emphasis: var(--eds-background-interactive-danger-emphasis-default);
    /* …the other slots */
  }
}
```

States and variants then set `--_color`, `--_bg-color` and `--_border-color` from those slots, never the properties directly.

## 5. Spacing and sizes

| Legacy                                                                                                                                      | Beta                                                                                                                     |
| ------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `--eds-selectable-space-{vertical,horizontal}`, `--eds-container-space-*`, `--eds-spacing-inset-*`, `--eds-spacing-{vertical,horizontal}-*` | `--eds-spacing-*`, picked from the Figma binding                                                                         |
| `--eds-generic-gap-horizontal`, `--eds-typography-gap-horizontal`                                                                           | `--eds-spacing-*`                                                                                                        |
| `--eds-sizing-icon-*`, `--eds-typography-icon-size`                                                                                         | `--eds-spacing-*`, as bound in Figma (Button uses `--eds-spacing-lg`, Chip `--eds-spacing-md`). There are no size tokens |
| `--eds-spacing-border-radius-{rounded,pill}`                                                                                                | `--eds-corner-radius-{none,rounded,rounded-outer,pill}`                                                                  |
| `--eds-sizing-stroke-*`, `--eds-border-width-default`                                                                                       | A plain `1px` (#5692)                                                                                                    |

The spacing scale at the default density (`comfortable`), in px:

| `none` | `4xs` | `3xs` | `2xs` | `xs` | `sm` | `md` | `lg` | `xl` | `2xl` | `3xl` | `4xl` | `5xl` | `6xl` | `7xl` | `8xl` | `9xl` |
| ------ | ----- | ----- | ----- | ---- | ---- | ---- | ---- | ---- | ----- | ----- | ----- | ----- | ----- | ----- | ----- | ----- |
| 0      | 2     | 4     | 6     | 8    | 12   | 16   | 20   | 24   | 28    | 32    | 40    | 48    | 64    | 80    | 96    | 128   |

**Density** is `compact`, `comfortable` (default) or `relaxed`, set with `data-density` on an ancestor. The bundle switches the values of the semantic names per density, so a component writes nothing per density. `spacious` no longer exists.

**Repad for untrimmed text.** Remove the trim and the baseline padding, and set symmetric padding from the Figma bindings. The line heights are multiples of 4px, so the component stays on the grid. Button: 8px + 20px line height + 8px gives 36px at `comfortable`.

**Icons inside a component** follow the component's size, not the Icon's `size` prop. Target `& > svg, & > .eds-icon[data-icon-size]` so the rule outranks Icon's own size rule, and drop Icon's optical margins when the icon is no taller than the line box. This is a breaking change for consumers who set `size` on such an icon.

## 6. Typography

Three roles (ADR-0027):

- **`header`** (Equinor, `xs`-`4xl`) for titles.
- **`label`** (Inter, `xs`-`5xl`) for single-line functional text: buttons, navigation, table cells, form labels, captions. Most `/next` component text is `label`.
- **`body`** (Inter, `sm`-`3xl`) for text that wraps.

| Legacy                                                                | Beta                                                         |
| --------------------------------------------------------------------- | ------------------------------------------------------------ |
| `--eds-typography-ui-body-font-family`                                | `--eds-font-family-ui` (headers: `--eds-font-family-header`) |
| `--eds-typography-ui-body-{size}-font-size`                           | `--eds-typography-{header,label,body}-{size}-font-size`      |
| `--eds-typography-ui-body-{size}-line-height-{default,squished}`      | `--eds-typography-{role}-{size}-line-height`, one per size   |
| `--eds-typography-ui-body-{size}-font-weight-{lighter,normal,bolder}` | `--eds-font-weight-{normal,medium,bold}`                     |
| `--eds-typography-tracking`, `--eds-padding-*-baseline`               | Remove                                                       |

Weight is never per size (ADR-0029). `header` is `medium` at every size, `label` is `normal`, `medium` or `bold`, and `body` is `normal` or `bold`. Sizes above `label` `5xl`, `header` `4xl` and `body` `3xl` have no beta equivalent.

The font family tokens carry a `sans-serif` fallback from `eds-tokens` 3.0.0-beta.10 (#5701), so do not add one in the component.

Set `font-family`, `font-size`, `line-height` and `font-weight` in the component CSS. Set them on the root as well as on inner text elements, so `asChild` elements get them too.

## 7. Local data attributes

Rename or remove the foundation attributes the component sets on its own elements:

| Today                                                    | After                                                    |
| -------------------------------------------------------- | -------------------------------------------------------- |
| `data-color-appearance`                                  | `data-tone`                                              |
| `data-selectable-space`                                  | `data-size` if the component has sizes, otherwise remove |
| `data-icon-size`                                         | `data-size`                                              |
| `data-space-proportions`                                 | Remove                                                   |
| `data-font-family`, `data-font-size`, `data-line-height` | Remove, and set the typography in the CSS (step 6)       |
| `data-baseline`                                          | Remove together with the trim                            |

- Always set `data-tone`, including for the default tone, so the component never picks up a tone from a parent.
- Never reuse the name of a global attribute such as `data-color-scheme` or `data-density` for a local variant (#5711).
- Write `data-size` and `data-tone` selectors together with the component class (`.eds-button[data-size='small']`). Several components share the names, so an unscoped `[data-size='small'] .eds-icon` would match icons inside a Button.
- Keep the attribute values the component's props already use. Button's sizes are `default` and `small`.

## 8. When a token is missing

1. Do not bridge it: no raw shades, no local hex, no px values, no hand-made variables, not even temporarily. `--eds-primitives-*` and `--eds-density-*` are internal names that can change without notice (ADR-0028 point 7) and count as workarounds. The `1px` stroke is the only sanctioned literal.
2. Search the existing issues, then open one issue per missing token in plain language: what the user sees, which token is missing and which component is blocked.
3. The PR stays in draft and lists the blocking issues. It moves to ready for review only when every token exists in a published `eds-tokens` beta release.

There is no motion token yet. Button and Chip use `150ms` with a `TODO` comment; do the same.

## 9. Verify

1. Every token name exists in the beta bundle. Grep each one; never assume a name from the pattern.
2. `pnpm run lint <file>` and the component's tests pass. Update tests and snapshots for the renamed attributes.
3. In Storybook, check every variant, tone, size and state against Figma, in light and dark mode, on `--eds-background-surface`, and in all three densities. Beta components are user-tested, so a known visible defect blocks the merge even when the cause is upstream.
4. Typography: no clipped descenders, line boxes on the 4px grid, nothing that relies on trim. Check the smallest and largest size.
5. Contrast: follow the contrast rules in `AGENTS.md` (the WCAG 2.1 AA minimum and the APCA targets, added in #5721). The token release already checks the documented foreground pairs, so measure only the pairs the component renders that are not on that list, from the resolved token values. Do not reuse numbers from earlier PRs or issues. Pairs below the target go in the internal discussion "APCA discrepancies in the beta colour tokens" (design-system-internal #317), in the format given there. They do not block the migration.
6. Compare the resolved values with `main`, so the PR can say what changed visually: heights, padding, icon sizes, weights.

## 10. PR

- Commit and PR title: `refactor!: migrate <Component> (next) to beta tokens`, no scope.
- Body: the mapping per domain, what changed visually against `main`, the APCA pairs below target with their discussion entry, blockers with issue links, and what was tested. Follow [`PR_AND_ISSUE_WRITING.md`](./PR_AND_ISSUE_WRITING.md).
- List under `BREAKING CHANGE:` what consumers notice: the renamed data attributes, that apps need the beta bundle and `data-color-scheme`, and icon sizing inside the component.
- When the PR merges, tick the component off in #5119.

## Checklist

| Mistake                                                    | Fix                                                   |
| ---------------------------------------------------------- | ----------------------------------------------------- |
| Token name assumed from the pattern                        | Grep the beta bundle                                  |
| `--eds-density-*` or `--eds-primitives-*` in component CSS | Use the semantic name                                 |
| Missing token bridged with a shade, primitive or px value  | Remove it, open an issue, keep the PR in draft        |
| 2px focus ring or ring gap carried over                    | `1px` (#5692)                                         |
| Property set directly in a state or tone selector          | Override the `--_` slot                               |
| `data-color-appearance` kept                               | `data-tone`, set for every tone including the default |
| `text-box` trim or baseline padding kept                   | Remove both and repad symmetrically                   |
| Per-size weight or `line-height-squished` carried over     | One weight per role, one line height per size         |
| Wrapping text on `label`, or button text on `body`         | `label` is single-line, `body` wraps                  |
| Fill judged against the canvas                             | Judge against `--eds-background-surface`              |
| Only `comfortable` checked                                 | Check `compact` and `relaxed` too                     |
| Contrast number copied from an old thread                  | Measure it again                                      |
| Only colour migrated                                       | Colour, spacing and typography in one pass            |

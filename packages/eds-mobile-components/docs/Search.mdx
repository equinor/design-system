## Features

- Shows a clear button inside the field while it has text. Pressing it empties the field, so the user can type a new query.
- Can show a Cancel button next to the field when you set `cancellable`. It slides in while the field is focused. Pressing it empties the field, closes the keyboard and calls `onCancelPress`, so the user can leave the search.
- Combines a label, a description, the search field and a helper message in one field.
- Shows an error icon next to the search icon while the field is invalid.

## Usage

```bash
npm install @equinor/eds-mobile-components
```

```tsx
import { Search } from '@equinor/eds-mobile-components'

<Search label="Search" placeholder="Search" />
```

## Examples

### With clear button

A clear button appears inside the field while it has text. Pressing it empties the field, so the user can type a new query.

```tsx
<Search label="Search" placeholder="Search" defaultValue="Equinor" />
```

### With cancel button

Set `cancellable` to show a Cancel button beside the field while it is focused. The clear button stays inside the field, so both work together: clear only empties the field, while Cancel also closes the keyboard and calls `onCancelPress`, so the screen can leave the search.

```tsx
<Search
    label="Search"
    defaultValue="Equinor"
    cancellable
    onCancelPress={handleCancel}
/>
```

### With description and helper

The description sits between the label and the field, and the helper message sits below it.

```tsx
<Search
    label="Search"
    description="Search across all resources"
    helperMessage="Enter at least 3 characters"
/>
```

### Invalid

Set `invalid` to show an error icon next to the search icon, and say what is wrong in `helperMessage`. Screen readers read it as part of the hint.

```tsx
<Search
    label="Search"
    invalid
    defaultValue="xyz"
    helperMessage="No results found"
/>
```

### Disabled and read only

A disabled field ignores input and is dimmed. A read only field shows its value without letting the user change it, and neither shows a clear button.

```tsx
<Search label="Disabled" disabled defaultValue="Cannot be changed" />
<Search label="Read only" readOnly defaultValue="Previous search" />
```

## Accessibility

- The `label` is the accessible name. A field with no label, or one that needs a different name, takes an `accessibilityLabel`.
- The description and helper message are joined into the accessibility hint, unless you pass your own `accessibilityHint`, so a screen reader reads them with the field.
- The clear button is a button named "Clear search", and the Cancel button is named "Cancel".
- The search, error and clear icons are hidden from screen readers.
- While `invalid` is set, the error icon is hidden from screen readers, so the helper message is the only place that says what is wrong. Write it to say what to fix.
- A disabled field is reported to screen readers as disabled. A read only field cannot be edited.

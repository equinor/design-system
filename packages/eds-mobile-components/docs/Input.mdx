## Features

- Adds prefix or suffix text, and adornments such as icons, at the start or end.
- Shows error styling and an error icon when invalid.
- Distinguishes disabled, which ignores presses and dims the input, from read only, which stops editing without dimming the input or marking it disabled for screen readers.
- Grows to fit multiple lines of text when `multiline` is set, so use TextArea instead when you need a complete, labelled field for multi-line text.

## Usage

```bash
npm install @equinor/eds-mobile-components
```

```tsx
import { Input } from '@equinor/eds-mobile-components'

const [value, setValue] = useState('')

<Input value={value} onChange={setValue} accessibilityLabel="Description of input" />
```

## Props

| Prop | Type | Default | Description |
|---|---|---|---|
| `onChange` | `(contents: string) => void` | None | A callback method invoked when the input component registers a change of text content. |
| `multiline` | `boolean` | None | A boolean value indicating whether or not the input component should span across multiple lines of text or wrapped to one line. |
| `placeholder` | `string` | None | The text to display when the input component is empty. |
| `startText` | `string` | None | Prefix text displayed at the start of the input (e.g., "https://", "NOK", "€"). |

| `startAdornment` | `ReactNode` | None | An element displayed at the start of the input (e.g., an icon or button). |
| `endAdornment` | `ReactNode` | None | An element displayed at the end of the input (e.g., an icon or button). |

| `hideErrorIcon` | `boolean` | None | Whether to hide the built-in error icon shown when invalid is true. |

## Examples

### States

An input is either at its default, disabled, or read only. Both disabled and read only stop editing, but only disabled dims the input and marks it disabled for screen readers. On iOS, selecting text in a read only input needs `multiline`, since single-line fields are not selectable there. `value` and `setValue` are a `useState` pair kept in the parent screen.

```tsx
<Input
    accessibilityLabel="Default"
    value={value}
    onChange={setValue}
/>
<Input
    accessibilityLabel="Disabled"
    value="Disabled value"
    disabled
/>
<Input
    accessibilityLabel="Read only"
    value="Read only value"
    readOnly
/>
```

### Validation states

Set `invalid` to show error styling and an error icon. Pair it with an accessible description of what needs fixing.

```tsx
<Input accessibilityLabel="Default" placeholder="Default" />
<Input accessibilityLabel="Invalid" placeholder="Invalid" invalid />
```

### With adornments

Use `startText` and `endText` for prefix or suffix text, such as a currency symbol or unit. Use `startAdornment` and `endAdornment` for elements such as icons.

```tsx
<Input
    accessibilityLabel="With text prefix and suffix"
    placeholder="Amount"
    startText="€"
    endText="EUR"
/>
<Input
    accessibilityLabel="With icon"
    placeholder="Website"
    endAdornment={<Icon name="link-variant" size={16} />}
/>
<Input
    accessibilityLabel="Search"
    placeholder="Search"
    startAdornment={<Icon name="magnify" size={16} />}
/>
```

### Multiline

Set `multiline` to let the input grow to fit several lines of text, such as a comment or a note.

```tsx
<Input
    accessibilityLabel="Message"
    placeholder="Write a message"
    multiline
/>
```

## Accessibility

- Input wraps a native `TextInput`, so it reports itself to screen readers with its current value and, when disabled, its disabled state.
- Needs an accessible name from `accessibilityLabel`, since Input has no built-in label of its own.
- On iOS, selecting text in a read only input needs `multiline`. Single-line read only inputs are not selectable there.

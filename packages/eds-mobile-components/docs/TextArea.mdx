## Features

- Combines a label, a description, the text area and a helper message in one field.
- Shows an indicator such as "(Optional)" after the label.
- Can show a character count, as "n / max" when `maxLength` is set.
- Announces the count to screen readers when it reaches 80% and 100% of `maxLength`.
- Shows an error icon while the field is invalid.

## Usage

```bash
npm install @equinor/eds-mobile-components
```

```tsx
import { TextArea } from '@equinor/eds-mobile-components'

<TextArea label="Message" placeholder="Write a message" />
```

## Props

| Prop | Type | Default | Description |
|---|---|---|---|
| `label` | `string` | None | Label displayed above the field. |
| `indicator` | `string` | None | Inline text after the label, e.g. "(Optional)". |
| `description` | `string` | None | Descriptive text below the label. |
| `helperMessage` | `string` | None | Message shown below the field. |
| `invalid` | `boolean` | `false` | Error state, shown with danger colours on the border and background. |
| `disabled` | `boolean` | `false` | Disables all interaction. |
| `readOnly` | `boolean` | `false` | Prevents editing. The value can still be selected and copied. |
| `showCharacterCount` | `boolean` | `false` | Shows a character count below the TextArea. Displays "n / maxLength" when maxLength is set, otherwise just "n". |
| `ref` | `Ref<TextInput>` | None | Ref to the text input. |

## Examples

### With description and helper

The description sits between the label and the text area, and the helper message sits below it.

```tsx
<TextArea
    label="Feedback"
    description="Tell us what we can improve"
    placeholder="Write your feedback"
    helperMessage="Do not include personal details"
/>
```

### With indicator

Use `indicator` for text such as "(Required)" or "(Optional)" after the label.

```tsx
<TextArea
    label="Comments"
    indicator="(Optional)"
    placeholder="Add a comment"
/>
```

### With character count

Set `showCharacterCount` to show the count below the field. With `maxLength` it reads "n / max", and a screen reader announces it when it reaches 80% and 100% of the limit.

```tsx
<TextArea label="Notes" maxLength={200} showCharacterCount />
```

### Invalid

Set `invalid` to show the error styling and icon, and say what to fix in `helperMessage`. Screen readers read it as part of the hint.

```tsx
<TextArea
    label="Message"
    invalid
    defaultValue="Hi"
    helperMessage="Write at least 20 characters"
/>
```

### Disabled and read only

A disabled field ignores input and is dimmed. A read only field shows its value without letting the user change it.

```tsx
<TextArea label="Disabled" disabled defaultValue="Cannot be changed" />
<TextArea label="Read only" readOnly defaultValue="Can be selected" />
```

## Accessibility

- The `label` is the accessible name, unless you pass your own `accessibilityLabel`.
- The description and helper message are joined into the accessibility hint, unless you pass your own `accessibilityHint`, so a screen reader reads them with the field.
- While `invalid` is set, the error icon is hidden from screen readers, so the helper message is the only place that says what is wrong. Write it to say what to fix.
- A disabled field is reported to screen readers as disabled. A read only field cannot be edited, but it is not reported as read only.
- With `showCharacterCount` and `maxLength`, a screen reader announces "n of N characters" when the count reaches 80% and 100% of the limit.
- A field with no label needs an `accessibilityLabel`.

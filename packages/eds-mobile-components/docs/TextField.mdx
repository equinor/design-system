## Features

- Combines a label, a description, the input and a helper message in one field.
- Shows an indicator such as "(Optional)" after the label.
- Passes every Input prop through, so it takes adornments, prefix and suffix text, multiple lines, read only and disabled.
- Dims the helper message while the field is disabled.

## Usage

```bash
npm install @equinor/eds-mobile-components
```

```tsx
import { TextField } from '@equinor/eds-mobile-components'

<TextField label="Email" placeholder="name@example.com" />
```

## Examples

### With description and helper

The description sits between the label and the input, and the helper message sits below the input.

```tsx
<TextField
    label="Email"
    description="We use it to send your receipt"
    placeholder="name@example.com"
    helperMessage="You can change it later in settings"
/>
```

### With indicator

Use `indicator` for text such as "(Required)" or "(Optional)" after the label.

```tsx
<TextField
    label="Nickname"
    indicator="(Optional)"
    placeholder="Enter a nickname"
/>
```

### Invalid

Set `invalid` to show the error styling, and say what to fix in `helperMessage`. Screen readers read it as part of the hint.

```tsx
<TextField
    label="Password"
    invalid
    defaultValue="abc"
    helperMessage="Use at least 8 characters"
/>
```

### Disabled and read only

A disabled field ignores input and is dimmed. A read only field shows its value without letting the user change it.

```tsx
<TextField label="Disabled" disabled defaultValue="Cannot be changed" />
<TextField label="Read only" readOnly defaultValue="Can be selected" />
```

### With start text

Use `startText` and `endText` for a prefix or suffix, such as a currency or a unit.

```tsx
<TextField label="Amount" startText="NOK" placeholder="0.00" />
```

### Multiline

Set `multiline` to allow text over several lines. TextArea is the complete field built for longer text.

```tsx
<TextField label="Notes" multiline />
```

## Accessibility

- The `label` is the accessible name, unless you pass your own `accessibilityLabel`.
- The description and helper message are joined into the accessibility hint, unless you pass your own `accessibilityHint`, so a screen reader reads them with the field.
- While `invalid` is set, the helper message is the only place that says what is wrong, so write it to say what to fix.
- A disabled field is reported to screen readers as disabled. A read only field cannot be edited, but it is not reported as read only.
- A field with no label needs an `accessibilityLabel`.

## Features

- Turns a setting on or off immediately, with no separate confirmation step.
- You own the active state. Pressing the switch reports the new value, and you pass it back in.
- Shows a soft highlight while it is pressed.
- Without a label it becomes a round touch target, for rows that already say what the switch controls.
- Reduces its opacity when disabled.

## Usage

```bash
npm install @equinor/eds-mobile-components
```

```tsx
import { Switch } from '@equinor/eds-mobile-components'

const [active, setActive] = useState(false)

<Switch
  label="Notifications"
  active={active}
  onChange={setActive}
/>
```

## Props

| Prop | Type | Default | Description |
|---|---|---|---|
| `onChange` | `(isActive: boolean) => void` | None | Called when the switch is toggled. |
| `active` | `boolean` | `false` | Whether the switch is on or off. |
| `disabled` | `boolean` | `false` | Disables interaction. |
| `label` | `string` | None | Text label displayed next to the switch. |
| `ref` | `React.Ref<View>` | None | Ref to the switch. |

## Examples

### Default

Without `active`, Switch starts off.

```tsx
<Switch label="Enable notifications" />
```

### Without label

Use this when the row content already says what the switch controls, so it can sit directly next to other controls with no extra wrapping. Give it an `accessibilityLabel`, and it renders as a round touch target.

```tsx
<Switch
    active={isEnabled}
    onChange={setIsEnabled}
    accessibilityLabel="Enable feature"
/>
```

### Disabled

A disabled switch ignores presses and shows less opacity.

```tsx
<Switch label="Locked setting" active={true} disabled />
<Switch label="Unavailable" active={false} disabled />
```

## Accessibility

- Switch sets the switch role automatically.
- It reports its active and disabled state to screen readers.
- The `label` is used as the accessible name unless `accessibilityLabel` is set.
- Always provide a `label` or an `accessibilityLabel`. A switch with neither has no name for screen readers.

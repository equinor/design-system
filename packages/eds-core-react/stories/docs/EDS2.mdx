# About the beta

Welcome to the next generation of the Equinor Design System! 🎉

> **Note on naming:** the versions are named after their release status. **Latest** is `eds-core-react` 2.x and `eds-tokens` 2.x, the components outside this section. **Beta** is the 3.0.0 beta, the components in this section. See [Versioning](https://eds.equinor.com/docs/Next/about/getting-started/develop/getting_started_development/#versioning) for the full explanation.

## What is the beta?

The beta is a complete redesign of our component library, bringing:

- ✨ **Updated design foundations** - New spacing scales, color system, and typography built with CSS variables
- 🎨 **Pure CSS styling** - Moved away from styled-components to vanilla CSS
- 🌗 **Flexible theming** - Support for dark mode and density modes (spacious/comfortable) via `data-*` attributes
- 🎯 **Enhanced accessibility** - Improved WCAG 2.1 AA compliance across all components
- 🚀 **Better performance** - Optimized with modern React patterns and reduced bundle size
- 🔧 **Refined APIs** - Cleaner, more intuitive component interfaces

<br />
## What Beta Means

The components in the **Beta** section are published as a beta. Beta is not a warning against using them:

- ✅ **Safe to adopt** - The components are published on the `beta` tag so that teams can start using them now. Expect small API changes before 3.0.0 is released, all listed in the [beta changelog](https://github.com/equinor/design-system/blob/main/packages/eds-core-react/src/components/next/CHANGELOG.md) with breaking ones marked. Beta is followed by a release candidate before the stable release, so there is a step between the API you see today and the final one. The theming layer (design tokens and the `data-*` attributes for density and colour scheme) is being reworked, so keep those references few and centralised
- 🤝 **Latest is still supported** - The Latest components in `@equinor/eds-core-react` 2.x are maintained until 3.0.0 is released. There is no need to stop using them
- 🧩 **Mixing is expected** - Use the Latest and `/next` components side by side in the same application, and adopt the new ones as they fit your work
- 🛠️ **Tooling for the migration from 2.x to 3.0.0** - We plan to provide codemods and AI-assisted rewrites so that moving from 2.x to 3.0.0 is not a manual job

## How to Use Beta Components

<br />

### 1. Browse in Storybook

You can explore all beta components right here in Storybook! Components are organized under the **Beta** section in the sidebar.

Each component has:
- 📖 Interactive documentation
- 🎮 Live playground to test props
- 🎨 Design examples and use cases
- 🔍 Code snippets for implementation

### 2. Install Beta Version

To actually use these components in your application, install the beta version:

```bash
npm install @equinor/eds-core-react@beta
```

### 3. Load Fonts

The beta components use two font families: **Inter** for UI text (buttons, inputs, labels) and **Equinor** for headings. Load both via the EDS variable font stylesheet in your HTML `<head>`:

```html
<link rel="stylesheet" href="https://cdn.eds.equinor.com/font/eds-uprights-vf.css" />
```

> **Important:** The older `equinor-font.css` only includes the Equinor font. If you only load that, UI components (Button, TextField, etc.) will fall back to a generic sans-serif because Inter is missing.

### 4. Import CSS

Import component styles separately in your application entry point (this is important for SSR compatibility):

```tsx
import '@equinor/eds-core-react/next/index.css'
```

### 5. Import from `/next` Entry Point

```typescript
import { Button, TextField } from '@equinor/eds-core-react/next'

function MyApp() {
  return (
    <form>
      <TextField label="Project name" />
      <Button>Submit</Button>
    </form>
  )
}
```

## When Will 3.0.0 Be Released?

The beta components will graduate to stable in a **single major release (v3.0.0)**, through a release candidate:

1. **Beta** (`3.0.0-beta.N`, today) - Components live under `/next`. Small breaking changes can still happen, and each one is listed in the changelog.
2. **Release candidate** (`3.0.0-rc.N`) - The components move out of `/next` and the 2.x components are removed, so the RC is exactly what will ship. The API is frozen and only fixes land. This is the time to test 3.0.0 in your application. RC versions are published on the `rc` tag, and `beta` points to the same version.
3. **Stable** (`3.0.0`) - The last release candidate is released as stable, with no further code changes.

The design tokens (`@equinor/eds-tokens`) go through the same phases at the same time.

The release candidate starts when:

- ✅ All components are implemented and tested
- ✅ Design team has approved final implementations
- ✅ Real-world usage has validated the APIs
- ✅ Documentation and migration guides are complete

This approach ensures:
- 🎯 One clear migration point for all users
- 📝 Complete migration guide covering all changes
- 🔄 Simple import path change (no component renaming)
<br />
## Migration Path

From the release candidate onwards:

```typescript
// Before (beta):
import { Button } from '@equinor/eds-core-react/next'

// After (release candidate and v3.0.0 stable):
import { Button } from '@equinor/eds-core-react'
```

That's it! No component name changes, just update the import path.

Applications still on the 2.x components get a migration guide when 3.0.0 is released, and we plan to ship codemods and AI-assisted rewrites so the move is not a manual job. Until then, 2.x stays supported and you can adopt `/next` components at your own pace.

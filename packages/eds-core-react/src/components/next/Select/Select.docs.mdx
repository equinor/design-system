# Select

Select lets the user pick a single option from a list. It does not support selecting several. For a long list that people need to search, use [Autocomplete](?path=/docs/eds-2-0-beta-inputs-autocomplete--docs) instead.

**Beta:** safe to adopt alongside EDS 1.0. The API may still change in small ways before EDS 2.0 becomes stable. See [About EDS 2.0](?path=/docs/eds-2-0-beta-about--docs) for what beta means.

## Features

- Uses the browser's native select, so the option list and keyboard use come from the browser. Where `appearance: base-select` is supported, the list is styled to match EDS.
- Links the label, description and helper message to the select for you.
- Keeps a read only select focusable and, when it has a `name`, still submits its value, while blocking changes.
- Shows groups of options as native `<optgroup>` sections.

## Examples

### States

A select can be default, disabled or read only. A disabled select cannot be focused and is left out of form submission. A read only select stays focusable and, when it has a `name`, still submits its value. A native `<select>` has no `readonly` attribute, so `readOnly` blocks changes itself and sets `aria-readonly`.

### Controlled

Use `value` + `onChange` for controlled state. The native `<select>` fires a standard `ChangeEvent<HTMLSelectElement>`. The helper message updates to reflect the current value.

<Canvas of={Stories.Controlled} />

### With placeholder

A `placeholder` renders as a hidden, disabled `<option value="">` and is pre-selected when no `value` or `defaultValue` is provided. It does not appear in the open dropdown. Its only role is to show hint text when nothing is selected. Once the user picks a real option they cannot return to the placeholder. This is a native constraint of `<select>`.

### With description

Use `description` for supplementary context below the label, `helperMessage` for guidance or validation feedback below the field, and `indicator` for a short label annotation such as "(Required)" or "(Optional)".

### Object options

When options are objects, provide `getOptionLabel` to specify which field to display and `getOptionValue` to specify the submitted form value. Pick an option and the helper message shows the id that would be submitted, while the trigger shows the human-readable name.

### Grouped options

Pass `SelectOptionGroup` objects in the `options` array to render native `<optgroup>` elements. Groups and flat options can be mixed in the same array. Pick an element and the helper message shows the group it belongs to.

Use `optionDisabled` to make specific options non-selectable. Disabled options are still visible in the list but cannot be chosen.

## Accessibility

- Select renders a native `<select>`, so the browser provides focus, keyboard behaviour and the option list.
- `label` renders a `<label>` tied to the select. Without a `label`, pass `aria-label` so the select has a name.
- `description` and `helperMessage` are linked to the select with `aria-describedby`, so a screen reader reads them after the label.
- `invalid` sets `aria-invalid` and shows an error icon, but does not block form submission, so use `required` for that. Use `helperMessage` to say what needs fixing, since the colour and icon alone do not explain it. The helper message is announced as an alert when it appears.
- A native `<select>` has no `readonly` attribute, so `readOnly` sets `aria-readonly` and blocks every key except Tab and Shift. The select stays focusable.
- `indicator` is shown, and read by a screen reader, as part of the label, but it does not mark the select as required. Set `required` on the select as well, so assistive technology and form validation know the field is required.
- `disabled` takes the select out of the tab order and out of form submission.

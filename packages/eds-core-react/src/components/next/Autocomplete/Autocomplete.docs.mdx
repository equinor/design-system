# Autocomplete

Autocomplete is a text input that filters a list of options as the user types, so they can pick one from a long list. It can also let them add a value that is not in the list. Use [Select](?path=/docs/eds-2-0-beta-inputs-select--docs) instead for a short list that needs no search.

**Beta:** safe to adopt alongside EDS 1.0. The API may still change in small ways before EDS 2.0 becomes stable. See [About EDS 2.0](?path=/docs/eds-2-0-beta-about--docs) for what beta means.

## Features

- Lets the user add a value that is not in the list. With `allowCustomValue`, an "Add" option appears while they type, and `onCustomValueConfirm` receives the typed text.
- Filters the options as you type, with a case-insensitive substring match that `optionsFilter` can replace.
- Accepts plain strings or objects as options, with `getOptionLabel` for objects and `renderOption` for custom rows.
- Supports server-side search. `loading` shows a spinner, and `optionsFilter` can return true for every option when the server has already filtered.
- Takes a `label`, `description` and `helperMessage` and links them to the input for you.

## Examples

### Controlled

Use `value` + `onValueChange` for controlled state. `onValueChange` fires with the selected option when the user picks from the list. The helper message updates to show the current value.

### States

An autocomplete can be default, disabled or read only. A disabled field cannot be focused or changed and is left out of form submission. A read only field keeps its value and can be focused, but cannot be changed and does not open its list.

<Canvas of={Stories.States} />

### Object options

When your options are objects instead of strings, provide `getOptionLabel` to tell the component which field to display and search by. `onValueChange` returns the full object. Notice the helper message shows both the name and the `id` field, which you would not have with a plain string list.

<Canvas of={Stories.ObjectOptions} />

### Custom option rendering

Use `renderOption` to show richer content per row, such as icons, subtitles and badges. `getOptionLabel` controls what appears in the input field after selection. `optionsFilter` controls what is searchable. Here it matches on both name and platform type, so try typing "fixed" or "semi".

<Canvas of={Stories.CustomOptionRendering} />

### Disabled options

Use `optionDisabled` to prevent specific options from being selected. Disabled options are still visible and keyboard-navigable but cannot be chosen.

<Canvas of={Stories.DisabledOptions} />

### Allow custom value

Use `allowCustomValue` to let users type and confirm a value not in the list. `onCustomValueConfirm` fires with the typed string. Use it to add the new value to your list and update the selection. Note: `onValueChange` is only called for existing list options; `onCustomValueConfirm` handles new values.

<Canvas of={Stories.AllowCustomValue} />

### Loading

Set `loading` while fetching async options. The spinner replaces the clear button and a loading message is shown. Combine with `onInputChange` to trigger server-side search as the user types.

<Canvas of={Stories.Loading} />

### Async

Server-side search pattern: pass `optionsFilter={() => true}` to skip local filtering, use `onInputChange` to trigger fetches, and toggle `loading` while waiting. The debounce avoids a request on every keystroke. `renderOption` adds richer rows without affecting what is searched or displayed in the input.

<Canvas of={Stories.Async} />

### With react hook form

Use `Controller` from react-hook-form and wire `value` / `onValueChange` to `field.value` / `field.onChange`. Pass `onClear={() => field.onChange(undefined)}` so clearing the field also resets the form value. `invalid` and `helperMessage` connect validation errors. A valid submit shows a success banner with a button to start over.

Autocomplete adapts to density modes via the `data-density` attribute on a parent element. Spacious is the default; comfortable provides a more compact layout for dense UIs. The dropdown items respond to density as well.

## Accessibility

- The input has the `combobox` role with `aria-expanded`, `aria-controls`, `aria-autocomplete="list"` and `aria-haspopup="listbox"`. The list is a `listbox` of `option` items.
- Arrow Down and Arrow Up move the highlight through the options. Enter picks the highlighted option, and Escape closes the list without picking one. Focus stays in the input, and `aria-activedescendant` points at the highlighted option.
- A hidden status region announces "No results" or the number of results as the user types.
- `label` renders a `<label>` tied to the input. Without a `label`, pass `aria-label` so the input has a name.
- `description` and `helperMessage` are linked with `aria-describedby`. With `invalid`, the helper message is announced as an alert when it appears.
- The clear button is named "Clear" and the loading spinner "Loading". Use `clearLabel` to translate the button name, and `loadingText` to translate the loading announcement and the text in the list. The spinner's name is not translated.

# Typography

Typography in EDS 2.0 has three roles on two typefaces. You pick a role by what the text does and a step by how large it should be, and the `data-density` attribute adjusts the size for you. This page shows how to set the typography custom properties in code. The documentation site has the guidance and the values:

- [Typography overview](https://eds.equinor.com/docs/Next/foundation/design-tokens/typography): the roles, the steps, weights, typefaces and density
- [The type scale](https://eds.equinor.com/docs/Next/foundation/design-tokens/typography-scale): where the sizes and line heights come from, and how each density maps onto them
- [Using typography](https://eds.equinor.com/docs/Next/foundation/design-tokens/typography-usage): the role and step for each case, heading levels and common mistakes
- [Token reference](https://eds.equinor.com/docs/Next/foundation/design-tokens/typography-reference): every token, with its value in all three densities

The custom properties come from the beta token bundle, `@equinor/eds-tokens/next/css/variables.css`. The decisions behind them are recorded in [ADR-0027](https://github.com/equinor/design-system/blob/main/documentation/adr/0027-token-variable-architecture-typography-roles.md) for the tokens and [ADR-0029](https://github.com/equinor/design-system/blob/main/documentation/adr/0029-typography-approach-for-eds-2-web.md) for the web.

## Status in the beta

The components in this Storybook have not moved to these tokens yet. They still read the 2.x token names, and several of them trim text with `text-box`. They move to the new tokens, without trimming, in [#5119](https://github.com/equinor/design-system/issues/5119). Defaults for `h1` to `h6` and `p` ([#5477](https://github.com/equinor/design-system/issues/5477)) and a class for each text style ([#5501](https://github.com/equinor/design-system/issues/5501)) have not shipped either, so the examples on this page set the custom properties directly.

## Three roles

Every piece of text takes one of three roles:

- **`header`** is for titles, the headings of pages and sections. It is set in Equinor, in the steps `xs` to `4xl`.
- **`label`** is for functional text on one line: buttons, navigation, table cells, form labels and captions. It is set in Inter, in the steps `xs` to `5xl`.
- **`body`** is for running text that wraps, such as paragraphs and descriptions. It is set in Inter, in the steps `sm` to `3xl`, with a line height of at least one and a half times the font size.

To choose between `label` and `body`, ask whether the text wraps, or could. The size of the text does not change its role, so a large key figure on a dashboard is still `label`.

A step is a font size and the line height that goes with it, and each is its own custom property. The family and the weight are separate tokens:

```css
.label {
  font-family: var(--eds-font-family-ui);
  font-size: var(--eds-typography-label-md-font-size);
  line-height: var(--eds-typography-label-md-line-height);
  font-weight: var(--eds-font-weight-normal);
}
```

The size names follow one pattern, `--eds-typography-{role}-{step}-font-size` and `--eds-typography-{role}-{step}-line-height`. The family is `--eds-font-family-header` for Equinor and `--eds-font-family-ui` for Inter. `ui` is only the name of the Inter family token, which `label` and `body` both use.

Load both typefaces with the EDS variable font stylesheet, `https://cdn.eds.equinor.com/font/eds-uprights-vf.css`. The older `equinor-font.css` includes only Equinor, so with it alone every `label` and `body` style falls back to a generic sans-serif.

Each role below is set with its own tokens, at its default weight. Use the density control to see every step move while the names stay the same.

## Weights

Weight is set separately from size, with three tokens: `--eds-font-weight-normal` (400), `--eds-font-weight-medium` (500) and `--eds-font-weight-bold` (700). Each role has a fixed set of them:

- `header` is always medium.
- `label` is normal by default, medium for text that needs emphasis, and bold for strong emphasis.
- `body` is normal by default, and bold for strong emphasis.

Weight does not change with size, so a `header.4xl` uses the same medium as a `header.md`. On the web, text in `<strong>` or `<b>` is bold whatever text surrounds it, and `<em>` and `<i>` keep the weight of the text around them and turn italic.

## Density

The `data-density` attribute on a wrapper resizes the text inside it, together with the spacing:

```html
<div data-density="compact">…</div>
```

Comfortable is the default, used where no attribute is set. Compact takes the font size and line height of the next smaller step, and Relaxed those of the next larger step, so a `label.md` in Compact is set like a `label.sm` in Comfortable. The custom property names are the same in every density, so the CSS does not change. The last worked example on this page shows one row in all three densities.

The earlier beta named the densities differently: its `spacious`, or no attribute, is now Comfortable, and its `comfortable` is now Compact.

## Line height without trimming

The web does not trim text. A line of text is as tall as its line height, as it is in the Figma text styles, and no padding or line height is adjusted to make up for trimming. Every line height is a multiple of 4px, so text stays on the same 4px grid as the spacing around it.

Set the line height wherever you set the font size, because text without its own line height inherits one from its parent. The first worked example below shows what that does to a caption.

## Worked examples

These are the worked examples from [Using typography](https://eds.equinor.com/docs/Next/foundation/design-tokens/typography-usage), with the CSS each one uses.

### Always set the pair

Take the font size and the line height from the same role and step. Both captions below sit in running text set in `body.lg`. The first sets both from `label.sm`. The second sets only the font size, so it inherits the line height of the running text, which in Comfortable is 28px where `label.sm` has 16px. The dashed outline shows the line box of each caption.

<Canvas of={TypographyStories.AlwaysSetThePair} />

```css
.caption {
  font-size: var(--eds-typography-label-sm-font-size);
  line-height: var(--eds-typography-label-sm-line-height);
}
```

### Hierarchy

Reach for size first, then weight, then colour, and change as little as you need to. This row in a list of wells has three levels of text: the name in `label.lg` at medium weight, the status in `body.md`, and the inspection date in `label.sm` with `--eds-text-secondary`. The name and the date stay on one line, so they are `label`. The status can wrap, so it is `body`, even though it sits between them in the hierarchy.

<Canvas of={TypographyStories.Hierarchy} />

```css
.well-name {
  font-size: var(--eds-typography-label-lg-font-size);
  line-height: var(--eds-typography-label-lg-line-height);
  font-weight: var(--eds-font-weight-medium);
}
.well-status {
  font-size: var(--eds-typography-body-md-font-size);
  line-height: var(--eds-typography-body-md-line-height);
}
.well-inspected {
  font-size: var(--eds-typography-label-sm-font-size);
  line-height: var(--eds-typography-label-sm-line-height);
  color: var(--eds-text-secondary);
}
```

### Page composition

An overview page, set with steps from the [decision table](https://eds.equinor.com/docs/Next/foundation/design-tokens/typography-usage#decision-table): the app name in `label.xl`, the page title in `header.4xl`, the ingress in `body.xl`, the key figures in `label.3xl` with their labels in `label.sm`, a section heading in `header.3xl` and running text in `body.lg`. The key figures use Inter's tabular figures, where every digit has the same width, so a value that updates does not shift sideways. The gaps between the elements frame the example and are not spacing guidance.

<Canvas of={TypographyStories.PageComposition} />

```css
.app-name {
  font-size: var(--eds-typography-label-xl-font-size);
  line-height: var(--eds-typography-label-xl-line-height);
}
.page-title {
  font-family: var(--eds-font-family-header);
  font-size: var(--eds-typography-header-4xl-font-size);
  line-height: var(--eds-typography-header-4xl-line-height);
  font-weight: var(--eds-font-weight-medium);
}
.ingress {
  font-size: var(--eds-typography-body-xl-font-size);
  line-height: var(--eds-typography-body-xl-line-height);
}
.figure-label {
  font-size: var(--eds-typography-label-sm-font-size);
  line-height: var(--eds-typography-label-sm-line-height);
}
.figure {
  font-size: var(--eds-typography-label-3xl-font-size);
  line-height: var(--eds-typography-label-3xl-line-height);
  font-variant-numeric: tabular-nums;
}
.section-heading {
  font-family: var(--eds-font-family-header);
  font-size: var(--eds-typography-header-3xl-font-size);
  line-height: var(--eds-typography-header-3xl-line-height);
  font-weight: var(--eds-font-weight-medium);
}
.running-text {
  font-size: var(--eds-typography-body-lg-font-size);
  line-height: var(--eds-typography-body-lg-line-height);
}
```

### Label versus body

The same paragraph in `label.md` and in `body.md`. Both have the same font size, and `body.md` has more line height (in Comfortable, 24px where `label.md` has 20px), which helps the eye find the next line in a block of text. Text that wraps, or could, is `body`.

### Heading level versus size

Choose the heading element by the structure of the page, and the header step by how it should look. Both headings below are `h2` elements. The first is at `header.3xl`, the step that goes with an `h2`. The second is a section heading on an overview page, set at the size of a page title, and it stays an `h2`. [Heading levels](https://eds.equinor.com/docs/Next/foundation/design-tokens/typography-usage#heading-levels) lists the step for each level.

<Canvas of={TypographyStories.HeadingLevelVersusSize} />

```css
.overview-page h2 {
  font-family: var(--eds-font-family-header);
  font-size: var(--eds-typography-header-4xl-font-size);
  line-height: var(--eds-typography-header-4xl-line-height);
  font-weight: var(--eds-font-weight-medium);
}
```

### Density

The row from the hierarchy example under `data-density="compact"`, `"comfortable"` and `"relaxed"`. The markup and the custom properties are the same in all three, and only the attribute on the wrapper changes. To fit a dense view, set Compact on a wrapper instead of picking a smaller step, which would reimplement Compact and drift from every other dense view in the product.

## Coming from the earlier beta

The earlier beta of this page described a different model: a computed `ui-body` scale with `default` and `squished` line heights, weights that changed with the step, and text trimmed to the baseline. In the current tokens, `ui-body` with a `squished` line height becomes `label`, and `ui-body` with a `default` line height becomes `body`. The `bolder` weight is now `medium`, at the same weight, and `lighter` is removed. The first beta releases of `@equinor/eds-tokens`, 3.0.0-beta.1 to 3.0.0-beta.7, named the Inter role `ui`, which is now `label`, or `body` for text that wraps.

[Coming from an earlier version](https://eds.equinor.com/docs/Next/foundation/design-tokens/typography#coming-from-an-earlier-version) maps every old name to its replacement.

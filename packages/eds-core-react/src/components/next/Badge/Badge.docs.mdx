# Badge

Badge labels content with a status, a category or a piece of metadata. Place a badge next to a heading, in a table, or on a list row or card, so readers can see at a glance what the item is.

Badge is non-interactive: it cannot be selected, focused or dismissed. For labels that users select, use [Chip](?path=/docs/eds-2-0-beta-data-display-chip--docs) instead.

**Beta:** safe to adopt alongside EDS 1.0. The API may still change in small ways before EDS 2.0 becomes stable. See [About EDS 2.0](?path=/docs/eds-2-0-beta-about--docs) for what beta means.

## Features

- Six `tone` values: `neutral` (neutral gray tones), `accent` (brand/action color), `success` (positive/confirmation), `info` (informational), `warning` (caution/alerts), `danger` (destructive/error). The default is `neutral`.
- Two `emphasis` values: `low` (subtle background (canvas) or light border), `medium` (more prominent fill or medium border). The default is `low`.
- Two `variant` values: `solid` (filled background, no border), `outlined` (border, transparent or canvas background). The default is `solid`.
- Accepts `ReactNode` as children.

## Examples

### Tones

Six semantic tones cover the full status spectrum. Use `success`, `warning`, and `danger` for operational states; `info` for informational labels; `accent` for categorisation; `neutral` as the default when no semantic meaning is needed.

<Canvas of={Stories.Tones} />

### Emphasis

`low` (default) uses a subtle background fill, which suits most inline use. `medium` increases the fill density for stronger contrast, useful when the badge needs to stand out on its own.

<Canvas of={Stories.Emphasis} />

### Variants

Solid (default) suits most contexts. Outlined uses a border instead of a fill, which is useful when the background is already coloured or when a lighter visual weight is preferable.

<Canvas of={Stories.Variants} />

### Inline with text

Badges sit inline with headings and body text. Use `align-items: center` on the flex container to align the badge baseline with the surrounding text.

<Canvas of={Stories.InlineWithText} />

### In table

Badges in table columns let users scan status and priority at a glance. Use `emphasis="medium"` for the more prominent priority column.

<Canvas of={Stories.InTable} />

### Multiple labels

Multiple badges per item communicate separate properties without cluttering the layout, for example location type, operational status and technical classification.

<Canvas of={Stories.MultipleLabels} />

### Density

Badge responds to `data-density` on a parent element. Comfortable reduces block and inline padding from 6px to 4px.

<Canvas of={Stories.Density} />

## Accessibility

- Badge renders a plain `span` with no role and no `tabindex`, so it is not focusable.
- Tone is applied through colour only and is not announced. Do not rely on colour alone to convey meaning; let the label text carry the status.

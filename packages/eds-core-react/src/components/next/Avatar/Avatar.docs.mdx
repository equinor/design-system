# Avatar

Avatar represents a person in a small circle, for example in lists and headers. Use `AvatarNameLabel` to show it next to the person's name.

**Beta:** safe to adopt alongside EDS 1.0. The API may still change in small ways before EDS 2.0 becomes stable. See [About EDS 2.0](?path=/docs/eds-2-0-beta-about--docs) for what beta means.

## Features

- Shows a profile photo, or initials when there is no photo.
- One `name` gives both the initials and the accessible name, so screen readers announce the person.
- Can show a notification dot that screen readers also announce.
- `AvatarNameLabel` has room for secondary text, such as a job title, and an open trailing slot that takes any content.

### AvatarNameLabel

| Prop | Type | Default | Description |
|---|---|---|---|
| `name` | `string` | None | Name of the person, displayed as the primary label. Also auto-derives the avatar initial. Required. |
| `meta` | `string` | None | Secondary label, such as an email, a job title or any short metadata |
| `layout` | `'horizontal' \| 'vertical'` | `'horizontal'` | `horizontal` stacks the name and meta, for lists with one person per row. `vertical` puts them on one line, for headers and other wide contexts. The names follow Figma and refer to the list the component sits in. |
| `initial` | `string` | None | Override the initials shown in the avatar, which are otherwise derived from the first and last word of `name` |
| `src` | `string` | None | Profile photo URL. When provided, renders a circular photo instead of initials. |
| `alt` | `string` | None | Alt text for the photo. Defaults to `""` (decorative) so the visible name is not announced twice. Pass a value to override. |
| `size` | `AvatarSize` | `'lg'` | Size of the avatar |
| `emphasis` | `AvatarEmphasis` | `'low'` | Colour emphasis of the avatar |
| `notification` | `boolean` | `false` | Show a red notification dot on the avatar |
| `children` | `ReactNode` | None | Optional slot for content to the right (e.g. an icon or action button) |

### Name label edge cases

The component fills its container. In **horizontal** layout long names wrap and the row grows with the content. **Vertical** layout keeps name and metadata on one line, truncated with an ellipsis, and is intended for wider contexts like headers or nav. Initials are always derived from the **first and last word**, regardless of how many names: `"Mary Jane Elizabeth Watson"` gives `"MW"`.

## Accessibility

- Avatar is not interactive. It has no `tabindex` and is not focusable.
- With `name` and no `src`, the avatar gets `role="img"` and an `aria-label` with the name. The initials themselves are hidden from screen readers.
- Without `name` or `src`, the avatar has no role and is decorative. Pass `name` when Avatar stands on its own.
- With `src`, the `img` carries the accessible name through `alt`, which falls back to `name`. Pass `alt=""` for a decorative photo.
- With `notification`, "notification" is added to the label (`"Ada Lovelace, notification"`). Without a label, a visually hidden "Notification" text is read out instead. The dot itself is hidden from screen readers.
- Inside `AvatarNameLabel` the avatar is decorative, and the photo gets an empty `alt` by default, so the visible name is not announced twice. Content in the trailing slot needs its own accessible name, such as an `aria-label` on an icon button.
